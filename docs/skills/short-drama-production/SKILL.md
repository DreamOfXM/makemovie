# 短剧生产总控

本 Skill 属于 `short-drama-studio`，与任何外部开源或商业项目无依赖、无引用。

## 硬规则

- 小说/原作为剧情唯一事实来源，不得新增、提前、调换事件。
- 每阶段先校验输入，再执行；失败即 `blocked`，停止后续阶段，不得静默重试、换模型、换 Provider 或改剧情。
- 用户未确认当前批次，不得生成下一批或合成整集。
- 生成图片/视频前必须先通过对应分镜和资产校验。
- 每个批次固定一个已授权且额度可用的模型；控制台“已开启/有额度”不等于当前 API Key 可用，批次开始前必须做真实端点探测。
- 生产报告必须区分“分镜规划完成、首帧完成、视频完成、合成完成”，不得用部分成片宣称整章完成。
- 任何阶段发现模型、参数、绑定或素材不符合规则，立即停止该批次。

## 阶段与闸门

1. 原文审计：建立事件顺序、时间地点、人物、道具、对白、伏笔、高潮清单；保留原文定位。
2. 剧本改写：只把叙述转为可拍摄动作/对白，逐项核对无遗漏、无新增、无调序；通过后才允许分镜。
3. 资产提取：角色、场景、关键道具去重；校验每个资产有唯一 ID、描述、参考图和来源。
4. 分镜拆解：按节拍分段，8–15秒/段，2–4子镜头；填写来源片段、入场/出场状态、角色/场景/道具绑定。
5. 提示词编译：图片 prompt 来自分镜首子镜头和绑定资产；视频 prompt 来自已校验 description。
6. 任务创建：校验项目/集/分镜归属、资产绑定、参考图存在、Provider/模型/能力一致、T2V/I2V/R2V 语义正确。
7. 批次验收：每批最多5段；逐段检查人物、场景、动作、道具、剧情、首尾连续性和音频。
8. 合成交付：所有批次经确认后，统一帧率/分辨率/色彩和音频，再合成并输出追溯报告。

## 生成物归属与追溯

每个生成物必须携带：`organizationId / projectId / episodeId / storyboardId / assetId / stage / sourcePrompt / provider / model / configVersion / taskId / objectKey / checksum / createdAt`

- 任务的项目、集、分镜和资产 ID 必须互相匹配；不匹配阻断。
- 生成完成后回写业务表：资产版本、首帧、分镜视频等。
- `GenerationTask` 保留完整参数快照；对象键由租户/项目/集/阶段/实体/版本生成，不使用用户文件名。
- 重新生成不得覆盖旧文件；保留旧 task 和 artifact，新版本标记为当前。

## 模型能力、额度与降级

- 必须用当前 API Key、当前端点、当前模型名做最小真实请求验证。
- 有首帧或角色参考图时，只允许 I2V/R2V；禁止降级到 T2V。
- R2V 传首帧+参考图组合；I2V 按模型契约传参，若不接受额外参考图则只传首帧。
- T2V 只允许无任何参考素材的任务。
- fallback 必须是能力兼容、已验证、去重的有序集合，并记录每次尝试的 HTTP 状态和脱敏错误。
- 成功提交后立即停止切换；轮询期间不得创建并发替代任务。

## 角色一致性

- 角色参考图为身份锚点（外貌/发型/体态）。
- 分镜图片必须传入实际出场角色参考图；多人镜头传入全部。
- 视频生成必须按模型要求附首帧和角色参考图。

## 连续性与音频

- 每段记录 `continuityIn/continuityOut`：人物位置、视线、动作、道具、光线、情绪。
- 相邻段出场状态必须等于下一段入场状态；不一致阻断。
- 生成前完成整章分镜规划和时长核算；完整章必须覆盖原文所有关键节点。
- 合成前统一分辨率、帧率、色彩空间和音频采样率。

## 结果状态

- `passed`：所有检查有证据，允许进入下一阶段。
- `needs_revision`：只修复失败实体。
- `blocked`：记录原因并停止。
