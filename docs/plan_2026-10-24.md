# plan_2026-10-24 · 分镜生成是整集质量的总闸门

> 起因：第 1 集成片 63 刀、208 秒，用户判定「主线不清、一直在跳、没有声音」。
> 人物一致性已达标。**分镜生成这一层做得好不好，直接决定整集产出好不好。**
> 本文件是整体规划：不改源码、不烧 API，批准后分批实施。

## 0. 三条硬要求（本规划的主干）

| # | 要求 | 在平台里落脚的地方 |
| --- | --- | --- |
| 1 | 把一集小说写成合理且优秀的分镜：哪里该长、哪里该短 | 剧本层节奏契约 + 分镜层「主镜优先」 |
| 2 | 长镜头多长取决于模型；超出就拆两段，**或者一颗镜头内拼两段视频**，两种都不能看出拼接 | 预检 + 连续段（take）+ 帧链 + 同镜拼接 |
| 3 | 镜头转换要自然，没有突兀和拼接感 | 转场决策表 + 音频桥 + 母带 xfade |

一句话：**这三条不是三个功能，是同一条链上的三个关卡——剧本写节奏、预检定能不能做、合成保证看不出来。**

## 2. 根因四条（带代码位置）

1. **剧本表是唯一真源，平台只转录**：`prompts.ts:133-136` 要求自带分镜表的剧本「durationMs 必须原样采用该行时长，不得按内容重新估算」。节奏决策权全在写剧本的人身上，平台不回头评估。
2. **分镜 prompt 没有「长镜头优先」**：`prompts.ts:151-156` 只说「反应、停顿和短动作可以取短」，还要求「一个镜头只承载一个连续的视听瞬间」——两句合起来在教模型往短里切。
3. **「一个镜头只能一个说话人」（`prompts.ts:153`）在后期配音下是伪约束**：本片声音走导入配音，口型不是硬约束；这条规则把一个能一镜说完的双人对白拆成两刀。
4. **碎不碎没人看**：分镜落库硬门只查字段在不在（`packages/pipeline/src/content-audit.ts:74-97`），审片门没有节奏读数。51 颗 ≤3 秒的镜头一路绿灯到母带。

## 3. 要求 1 · 长短镜怎么选

标签 **[意见]**：镜头语法的通行做法，不是本平台实测阈值；实施时作为起始默认，可按项目改。

| 内容形态 | 建议时长 | 为什么必须一镜 | 本集对应 |
| --- | --- | --- | --- |
| 一场戏的开场（交代空间、谁在哪、什么关系） | **8–10s** | 观众建立空间要时间；切碎后每次切都像换了房间 | 卧室、浴室各被切成 4–5 颗 2 秒 |
| 一个连续动作（起身→走到门口→停住） | **8–12s** | 拆开丢因果，接起来必然「跳」 | 第 3–5 镜 |
| 情绪推进（对视、犹豫、转身离开） | **6–10s** | 2 秒只够「发生」，不够「感受」 | 第 6 镜「他没有出门」 |
| 空镜／氛围／时间流逝 | **8–15s** | 天然呼吸点，也是最便宜的喘息 | 走廊灯灭、字卡前黑场 |
| 单人长句对白／VO 铺底 | **6–10s** | 一句话说完就要 6 秒以上 | 9 颗台词镜里 6 颗是 VO |
| 说话人特写切换 | 2–4s | 必须切，硬切正确 | 不用改 |
| 插入（手、道具、钟表读数） | 1–2s | 强调性，短是对的 | 床头钟 7:07:12 |
| 跨地点／跨时间 | 3–5s + 转场 | 短可以，但接缝必须处理 | 18 刀裸切 |
| 字卡／计数（第 N 次） | 1.5–3s | 节奏点，不是叙事镜 | 7 颗字卡 |
| 蒙太奇（重复第 N 次） | 0.8–2s ×N | 刻意碎，但要有节奏设计 | 后半段字卡墙 |

**最关键的一条：本集 85% 片长是无对白镜头**——正是最适合长镜头的部分，却切得最碎。

### 落地：剧本层节奏契约

`Project` 增 `shotRhythm`（`{avgShotMs, longTakeMinMs, longTakeShareMin}`，设置页可改）；`ScriptVersion` 增 `rhythm`（批准时平台从镜头表算，不让模型填）。`buildScriptPrompt` 追加：

```
节奏契约（与场景标记同级）：
- 先写场次表：场次 / 地点·时间 / 在场人物 / 这场戏推进什么 / 从上场怎么进来 / 怎么退出到下场 / 声音床。
- 再写镜头表：每镜必须带「镜头类型」= 主镜 / 插入 / 反应 / 空镜 / 字卡。
- 每个场景至少 1 颗主镜，时长 8–15 秒；主镜承载这一场最重要的连续动作或完整对白，不得把连续动作拆成多颗。
- 无对白的段落（情绪、空间、氛围）优先用一颗 6–12 秒的镜头，不要切成多颗短镜。
- 全片平均镜长不低于 {avgShotMs}；≥{longTakeMinMs} 的镜头合计占片长不低于 {longTakeShareMin}。
- 每镜的「声音」列写这一镜的环境音床（雨、脚步、电流、心跳…），允许写「无」。
```

**门**：仅对自带镜头表的剧本生效。硬门一条——表里算出的 avg／长镜占比低于项目设置时，批准按钮要求显式勾选「我接受这个节奏」（平台不自造阈值）。软读数不拦：≥8s 镜数、≤3s 连续段、刀/分钟、无对白镜平均时长。

设置页在三个阈值旁必须标「起始默认，非实测阈值」——它们是镜头语法的通行做法，不是本平台跑出来的数。

## 4. 要求 2 · 长镜头超出模型能力怎么办

### 4.1 已有的底子（不用重建）

- `ModelCapability.spec.duration` 支持 `range / steps / fixed` 三种声明。
- `resolveShotDurationCeiling` 已做「项目档 ≤ 模型上限 ≤ 产品 30 秒」三取最小，设置页有 10/15/30 三档。
- 项目绑定的 `wan2.6-i2v` 声明 2–15s，`wan3.0-video-prime` 2–30s（DB 实测）。

**适配器现状要说准**：本项目实际绑定的 dashscope/wan 适配器只读 `first_frame`（`packages/providers/src/dashscope.ts:170-171`，没有首帧直接抛错）。kling / veo / seedance 三个适配器接受 `last_frame`，但 `apps/worker` 与 `packages/pipeline` 里对 `last_frame` **零引用**（两边 grep 都是 0 命中）——平台从不产生、也从不传这个帧。所以下面 §4.4 的帧链**不能写成「复用已有 last_frame 能力」**：要走 `first_frame` 链接，末帧由平台自己抽。

### 4.2 缺的第一件：能力要有证据

`ModelCapability` 增 `durationEvidence`：`{source: 'probe'|'doc'|'manual', url, checkedAt, verifiedMs, taskId}`。

- 优先级：**实测（发一次最小合法请求，记录 acceptedMs / billedMs / 报错码）> 厂商文档（存 URL + 抓取日期）> 人工填写**。
- 界面读作「30 秒（文档 2026-10-20，未实测）」，不把声明当能力。
- 现有 `probeStatus` 只验连接与凭据，不验时长——扩一个时长维度；只在首次绑定、文档变更、首次用到该档位时探。**探一次要花钱，先报账再点。**
- 被实测证伪（宣称 30 实际 15）→ 自动把该模型上限降到实测值，设置页显示「能力声明已降级」。

### 4.3 缺的第二件：剧本批准前预检

逐镜比 `intentMs` 与 `effectiveMs`；超出的**不静默截断**，批准页列出「本集有 N 颗镜头超出模型能力」，每颗给三个选项：

| 选项 | 什么时候选 | 代价 |
| --- | --- | --- |
| **同镜拼接**（一颗镜头内接 N 段视频） | 拆点在同一空间、同一动作/情绪延续——观众不该察觉有切 | 多几次生成调用；接缝要靠帧链保证 |
| **拆成两镜** | 拆点本身就是叙事该切的地方（换机位、换信息、时间跳） | 可以换机位、可以用转场，但要真的自然 |
| **换模型** | 只是这一颗想拍长，且已绑定模型里有能买到的 | 单价可能更高 |

**40 秒的镜头在本平台必然要拆**：产品上限 30 秒。机制必须默认支持，不能当例外。

### 4.4 「同镜拼接」怎么做才看不出来

数据形态：新表 `ShotTake`——`{id, storyboardId, order, plannedMs, promptDelta, firstFrameArtifactId, endFrameArtifactId, videoArtifactId, status}`。一颗 Storyboard 可以有 1–N 条 take；**镜头卡上仍显示为一颗镜头**；母带里同组 take 之间**不加转场**。

**这一改动的爆炸半径必须算清（不能当「加一张表」）**：现有链路处处假设「一颗镜头 = 一个视频产物」——

| 消费方 | 现假设 | 要改什么 |
| --- | --- | --- |
| 合成快照 `Composition.manifest` | `storyboardIds[]` + `resolved` + `selections` + `audio`，每镜一个产物 | 快照里补 `takes[]`：每镜的 take 顺序与各自的 videoArtifactId、`spliceMs`；同组字段固化 |
| 编辑文档 `EpisodeEdit` / `EditMedia` | 时间线 clip 指向 `artifactId`，一镜一刀 | 一个 storyboard 可能落成 N 个 clip 或 1 个拼好的 artifact，取决于合成策略，必须二选一并写进快照 |
| 新鲜度指纹 | `Composition.inputFingerprint`（`schema.prisma:93-94`）+ 快照内 `editSnapshot.fingerprint` | take 任一变化（重跑某段、换末帧、改拆点）必须让指纹失配，否则旧渲染冒充当前 |
| 选版 CAS | `Storyboard.selectedVideoArtifactId` 单值 | 选版要落到「整镜的 take 集合」而不是单值；人工选某一段时其余段如何跟随要定规则 |
| 存量集 | 每镜 1 artifact | 迁移时把现有 artifact 包成 `order=1` 的唯一 take，编辑文档不必重写 |

所以实施上分成 S2c（数据 + 生成 + 帧链，镜头卡仍可单段跑通）和 S2d（合成快照 / 编辑文档 / 指纹 / 选版这四条消费链 + 存量迁移），见 §7。

四条不变量（少一条就能看出拼接）：

1. **帧链**：`take[n+1].firstFrameArtifactId` 必须就是 `take[n].endFrameArtifactId`（同一 artifact，像素差为 0）。这是确定性判据，不靠阈值。
   - 走 **`first_frame` 一条路**：段 n 出片后由平台抽末帧（抽 2–3 个候选避开崩坏帧）→ 存 artifact → 作为段 n+1 的 `first_frame` 发出。不依赖任何模型的 `last_frame` 入参。
   - 现状缺口：`apps/worker` 与 `packages/pipeline` 都不产生末帧 artifact，也没有「段→段」的引用；这条链是全新的一环。
2. **同机位**：同组 take 共享 location、主帧、机位与焦段描述；允许的运动只有推/拉/摇的连续延伸，禁止换角、越轴。
3. **同声床**：一条环境音跨所有 take 不断；台词只在句间停顿处切分。
4. **同参考集**：同组共享角色参考图与风格，不因分段而换 seed 策略。

拆点规则（写进 prompt，落库校验）：只能切在**动作完成点 / 视线转移 / 句间停顿 / 声音重音**上，禁止切在同一动作中段；相邻段 `continuityOut` 与 `continuityIn` 必须逐字承接，不许写「同上」；段长尽量均分。

**兜底**：某段失败只重跑该段，不重烧整颗镜头。

## 5. 要求 3 · 转场怎么自然

核心判据：**先看接缝有没有「锚点」。有锚点时硬切才对吧，没有锚点才需要过渡。** 这也是不做「一键全加」的原因。

| 接缝情况 | 用什么 | 说明 |
| --- | --- | --- |
| 同一动作跨切（手伸向门把 → 握住） | **硬切（匹配剪辑）** | 动作接动作，观众看到的是连续动作 |
| 同一视线／同一构图／同形状 | **硬切** | 位置与形状对齐，切了也像没切 |
| 同一空间换机位、时间小幅推进 | **硬切 + 音频桥** | 环境音提前 0.3–0.5s 进、上一场拖 0.2s 出 |
| 跨空间／跨时间／跨世界（真人 ↔ 元叙事界面） | 叠化 0.3–0.5s 或黑场过桥 | 本集 18 刀裸切属于这类 |
| 章节／字卡／世界切换 | 黑场过桥 | 字卡镜已自带淡入淡出 |
| 情绪断裂／时间回环 | 闪白 1–2 帧 **[意见]** | 「第 N 次」这类回环可用 |

执行分工：

1. **音频桥先做**（不动物时间轴，零视频重编码）：先验证「突兀感是不是主要来自声音断层」。
2. **叠化**走母带滤镜图 `xfade`（母带本来就为角标/字幕重编码，`media/src/index.ts:1103-1137`）；每处叠化缩短总长，**配音与字幕时间轴必须按累计 overlap 重算**。
   - 每刀的 overlap（哪一刀、多少 ms、缩短了多少总长）必须写进合成快照的 `resolved`，并参与 `Composition.inputFingerprint`。否则同一批素材换一次转场、指纹不变，旧母带会冒充当前。
   - xfade 的起始用时取 0.3–0.5s 区间逐刀试看，不设全片定值。
3. **帧链硬接**：同场连续动作的两镜，只要共享空间，就可以用末帧链把硬切做成「同一张图接同一张图」。
4. 转场数据：`Storyboard` 增 `transition`（硬切/叠化/淡入/淡出/黑场/闪白）、`transitionMs`；分镜契约表加「转场」列，默认硬切；存量按 `continuityIn` 以「新场景：」开头 → 叠化，明写「淡入」→ 淡入，实拍↔字卡保持现状。

## 6. 五层总图

```
剧本   场次表（进入/退出方式 + 声音床）+ 镜头表（镜头类型 + 意图时长 + 转场）
  ↓    平台出「节奏读数」，批准前必须看
预检   镜头意图时长 vs 模型证据化能力 → 同镜拼接 / 拆镜 / 换模型（人工确认）
  ↓    超长镜头在这里被切开，不拖到生成阶段才失败
分镜   主镜优先 → 再补插入/反应；一个连续动作不许拆；take 分组与拆点
  ↓
生成   按内容买时长；长镜先实测再放开；段间帧链
  ↓
合成   同组 take 无转场拼接；镜间按转场决策表；声床与音频桥；BGM/环境音门
  ↓
验收   节奏 / 转场 / 声音 三读数进审片门；缺一项只出草稿
```

## 7. 分批实施

| 批次 | 改动面 | 现金成本 | 验收点 |
| --- | --- | --- | --- |
| **S0 收口在途** | 先把手头 202 个未提交改动落定（提交或独立分支），再开本规划 | 0 | 工作树干净；S1 有可回退基线 |
| **S1 剧本层** | `prompts.ts` 节奏契约 + `packages/pipeline/src/content-audit.ts` 节奏读数 + 剧本批准页 + `Project.shotRhythm` | 0 | 本集剧本被拦一次，读数「63 镜 / 2.86s / 长镜 0 / 81% 短镜」可见 |
| **S2 分镜层** | 主镜优先 + 转场列 + 镜头类型列 + 镜内多句台词（`lines`）+ `shotRole/transition/transitionMs` | 0 | 新一集分镜出现 ≥8s 主镜，且每场有进出方式 |
| **S2b 预检** | `durationEvidence` + 批准前预检 + 超长三选一 | 0（探测那一次另报） | 一颗 40s 意图被识别并给出三个选项 |
| **S2c 连续段（数据与生成）** | `ShotTake` 表 + 拆点校验 + 段间帧链（抽末帧→first_frame） | 0 | 一颗 40s 意图拆两段，段 2 用段 1 末帧接上，逐帧看不出接 |
| **S2d 连续段（消费链）** | 合成快照 `takes[]` + `EpisodeEdit`/`EditMedia` 落 take + `inputFingerprint` 纳入 take + 选版 CAS + 存量集迁移 | 0 | 一段重跑后旧母带被判过期；存量 63 镜照常合成 |
| **S4① 声音** | 音频桥 + 声床导入（剧本「声音」列落库消费） | 0 | 第 1 集返修版可听出连续声场 |
| **S3 长镜实测** | 2 颗 8s + 1 颗 12s 实测，通过才放开 15s | ≈¥0–14.4（先查余额再报） | 一致性不塌 |
| **S4② 转场** | xfade + 时间轴重算 + overlap 写快照/指纹 + 22 刀回填 | 0 | 18 刀裸切处理后的母带 |
| **S5 验收** | 三读数进审片门（含母带实测时长探测入库） | 0 | 三项齐全才能点「合成完成」 |

## 9. 不做清单

1. 不重拍 63 镜——画面一致性已达标，问题在分镜与叙事层。
2. 不做「一键全加转场」——同场连续动作加转场只会更差。
3. 不让 LLM 判「剧情是否合理」——判不准，且把生成次数烧在判卷上。
4. 不在主镜实测通过前把 15 秒写进默认契约。
5. 不把「模型声明的上限」当已验证能力——没实测就标未实测。
6. 不在第 1 集闭合验证前开第 3 集。
